2. Creating An App

Creating an App

An app is a consumer. It calls capabilities through the Manager and never touches a worker. This is the easy half — the whole secure transport is one helper.

Step 1 — The project

A plain console/exe that references XRUIOS.Interfaces. That's all — an app never references Eclipse, Notary, or a worker directly.

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net9.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\XRUIOS.Interfaces\XRUIOS.Interfaces.csproj" />
  </ItemGroup>
</Project>

Step 2 — Get credentials (two supported ways, neither on disk)

An app needs its appId, per-app PSK, and the broker address. There are two ways to receive them, and the app can support both:

using XRUIOS.Interfaces;

// (a) env handoff — if the Manager SPAWNED us, our creds are already in the environment.
string? appId  = Environment.GetEnvironmentVariable("XRUIOS_APP_ID");
string? pskB64 = Environment.GetEnvironmentVariable("XRUIOS_APP_PSK");
string? broker = Environment.GetEnvironmentVariable("XRUIOS_BROKER_ADDR");

// (b) self-enroll — if we're our own exe, ask the Manager. It ATTESTS our binary
//     (verifies we're the registered app) before handing anything back.
if (appId is null || pskB64 is null || broker is null)
{
    var prov = await XruiosEnrollment.EnrollAsync("myapp");   // throws if attestation fails
    appId = prov.AppId; pskB64 = prov.PskBase64; broker = prov.BrokerAddress;
}
byte[] appPsk = Convert.FromBase64String(pskB64);
Why two ways? Env handoff is what you get when the Manager launches you (or Manager run myapp). Self-enrollment lets your app be its own standalone exe — double-click it and it enrolls itself. Both leave no secret at rest: env is parent→child, enrollment is over an attested local pipe. See 2 - Attestation and Enrollment.

Step 3 — Open one session and call capabilities

Open one EclipseSecureClient for the app's lifetime and reuse it — don't reconnect per call.

await using var xruios = await EclipseSecureClient.ConnectAsync(
    serverAddress: broker,
    clientName:    appId,
    psk:           appPsk,
    identity:      appId);      // stable id — the Manager keys permissions on it

// Call a capability by name. The Manager routes it to the owning worker after a permission check.
string forecast = await xruios.InvokeAsync<string>(
    "GetForecast", new Dictionary<string, object?> { ["city"] = "Höllvania" });

Console.WriteLine(forecast);

Step 4 — Handle refusals

If your app wasn't granted a capability, the call throws with the Manager's message. Catch it:

try
{
    await xruios.InvokeAsync<string>("DeleteAllEvents", new() { ["confirm"] = "yes" });
}
catch (Exception ex)
{
    // "Worker call failed: XRUIOS.Permission denied 'DeleteAllEvents' for app:myapp."
    Console.Error.WriteLine(ex.Message);
}
The refusal is enforced at the Manager, before anything reaches a worker. A denied app learns nothing about the worker — not even that the capability exists.

The whole app, end to end

using XRUIOS.Interfaces;

string? appId  = Environment.GetEnvironmentVariable("XRUIOS_APP_ID");
string? pskB64 = Environment.GetEnvironmentVariable("XRUIOS_APP_PSK");
string? broker = Environment.GetEnvironmentVariable("XRUIOS_BROKER_ADDR");
if (appId is null || pskB64 is null || broker is null)
{
    var prov = await XruiosEnrollment.EnrollAsync("myapp");
    appId = prov.AppId; pskB64 = prov.PskBase64; broker = prov.BrokerAddress;
}

await using var xruios = await EclipseSecureClient.ConnectAsync(
    broker, appId, Convert.FromBase64String(pskB64), identity: appId);

var forecast = await xruios.InvokeAsync<string>("GetForecast", new() { ["city"] = "Höllvania" });
Console.WriteLine(forecast);
You still have to register the app with the Manager — mint its creds, grant it capabilities, and (for self-enroll) put its exe in the catalog. See 4 - Registering and Launching. An unregistered app gets "no such registered app" on enrollment, and an ungranted capability is refused.
